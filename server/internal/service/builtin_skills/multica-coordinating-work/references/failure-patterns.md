# 交付故障处理案例

以下是应按当前证据选择的处理方式，不是每次任务都要运行的清单。历史案例不能替代现场核对。

| 信号 | 先确认什么 | 正确处理与证据 |
| --- | --- | --- |
| 独立验收因别人上线失效 | 自己的源码、产物、环境、种子与租约是否真的变化 | 原候选未变就复用验收；最终 int 检查新基线，不能让独立验收无限追主分支 |
| 新发布器拒绝接续旧任务 | 旧控制进程是否仍活动、保留子进程是谁的、原作业和缓存是否匹配 | 活动控制器不能双重接管；已退出且身份一致时用原生交接续接，不杀环境服务或重建交付 |
| Git merge 或 Go build 失败 | 真实服务用户、HOME、Git 身份、工具链和完整原始错误 | 修服务入口而非仅交互 shell；区分真实冲突与环境错误，不能让 merge abort 的错误覆盖原错误 |
| 新功能检查没有执行 | 本次运行的执行器版本，而不是候选源码版本 | 验证旧执行器安装新版的完整交接；新包里的门禁不能约束尚未升级的旧进程 |
| 刷新交付后 409 | 当前 revision、publication generation 和占用方 | 通过正常入口刷新并检查身份，不丢失代次，不伪造租约；锁释放后正常接续不等于抢锁 |
| 验收接力收到 409 就隔离槽位 | 服务端拒绝的是哪个写入：该执行是否仍是当前触发评论的最新运行、交付阶段是否已变 | 围栏是协议内的正常结果：保留租约与候选、不回填失败，由最新执行结束后的常规路径决定去向；兜底异常路径不能把被拦下的写入重做一遍，也不能污染正常槽位 |
| 外部验收归属结束后无人接续 | 准确候选是否已提交验收、有效归属、实际执行和通知是否真正送达 | 已提交证据优先处理；外部归属有效时等待，结束且无执行时补派一次；延后通知不算送达，固定通知标识持久幂等 |
| 交付已取消，后续发布仍排队 | 批次、每个成员和候选的实际状态，是否仍有活动发布器 | 交付取消不代表批次结束；由正常入口收敛失效批次并重排有效成员，重排、撤回和失败回填不得改写已取消或已发布的完整交付记录；以真实阶段和事务行锁处理取消与晋级竞态，不能仅凭旧授权判断成员有效 |
| 进度为零但模型仍执行 | 最新工具调用、回传时机、租约、实际任务 ID | 零条报告不等于未扫描；租约失效后等待无法恢复结果。由执行生命周期保证续租，不仅靠提示词 |
| 小批和大批都没有产出 | 真正 start/report/finish 链路与模型行为 | 小批只是缩小定位范围，不能掩盖没有回传、生命周期断裂或取消不收敛；保留失败证据 |
| 审查结论晚于发布或只核对旧源码 | 最新审查结论对应的源码、修复提交和实际部署版本 | 发布前消费准确候选的最新结论；承接已有发现与修复，只补新增风险，不将补丁存在当上线，也不并行重复调查 |
| 审查迟迟不返回 | 真实审查是否已派发、是否被无关历史任务占用 | 用专属 fixture 验证入口和结果；不要等待不受控的种子任务充当验收 |
| 所有 API 都 200 但功能未证实 | 返回的 skipped、任务 ID、终态、内容和持久化 | 不把通道测试冒充真实模型或外部 trace 对照；按业务要求逐项核实 |
| 注入上下文的测试通过，真实请求没有新行为 | 实际 JWT、PAT、托管凭据分别产生哪些身份上下文 | 复用已授权的具体任务访问结果，逐条真实鉴权入口验证；不能假设所有合法请求都会带同一个内部身份字段 |
| 工作成果已推送，但执行被提交起点守卫拒绝 | 最终提交是否仍包含本轮开始时的 HEAD | 在原分支正常合入修复，保留本轮祖先；重排检查点不能冒充历史未改写。独立已推送成果可正常承接，不重做代码 |
| 测试提示鉴权/只读/控件错误 | 测试请求的认证、路径匹配、实际产品契约 | 先修测试入口；不能将错误断言直接认定为产品缺陷，也不能删除必要断言装作通过 |
| 模型验收因配置失败而等待 | 当前环境可用的明确模型、实际运行终态和原配置 | 使用环境已验证模型；失败 fixture 通过正常接口取消并保留记录，确认终态后恢复原配置，不能把模型配置失败算作业务通过 |
| 只想编译却触发数据库操作 | `go test -run` 仍会执行 TestMain，检查已显式隔离的 DSN | 纯编译使用 `go test -c`；运行测试前验证独占数据库，不能把空测试正则当作无副作用 |
| 管道显示成功但测试失败 | 实际子命令退出码和失败输出 | 用直接退出码或 pipefail，不能以 tail/过滤命令成功代替测试成功 |
| 迁移账实不符 | 每个环境实际结构、完整必需版本和 ledger | 分环境求差集，不能把 prod 缺一条套给 int；正常迁移工具记录台账，不手工伪造。涉及删除要准确授权和实际恢复验证 |
| 数据被标成精确却对不上 | 标识来源强弱、session/trace/run 的真实关系 | 弱推断不能覆盖准确关联，强来源升级要一起校正关联字段；元数据记录冲突不等于关联已正确 |
| 多 Agent 都在分析同一发布问题 | 唯一公共依赖及当前调查者 | 一人定位公共根因，其他任务继续独立工作，分发短结论；不能人人重新读一遍发布源码 |
| 评论发了但行为没变 | 当前执行是否真的消费该评论 | 回执只证派发，工具轨迹才证读取；正常检查点续接一次，不靠反复 mention 或重复启动 |

处理一次后把可复用判断写入技能，把确定性约束写入代码。临时路径、任务号、版本和当前队列不是常驻规则。
