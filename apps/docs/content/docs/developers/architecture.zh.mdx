## 总览

Multica 是 Go 后端 + Next.js Web + Electron 桌面端 + PostgreSQL 的 monorepo。团队内部使用时，后端负责 API、WebSocket、任务队列、trace、usage 和训练评估数据；daemon 负责在具体电脑上执行 Agent CLI。

```text
浏览器 / 桌面端
      ↓ REST / WebSocket
Go 后端（Chi、任务队列、实时事件）
      ↓ sqlc
PostgreSQL（业务数据、trace、usage、训练评估）
      ↑
daemon（Codex / Claude / OpenCode / CodeBuddy 等运行时）
```

## 目录

| 目录 | 作用 |
| --- | --- |
| `server/` | Go 后端、CLI、daemon、migration |
| `apps/web/` | Next.js Web 应用 |
| `apps/desktop/` | Electron 桌面端 |
| `apps/docs/` | 文档站 |
| `packages/core/` | 跨端业务逻辑、API client、类型和 store |
| `packages/ui/` | 基础 UI 组件 |
| `packages/views/` | Web/桌面复用业务页面 |

## 后端

- `cmd/server`：HTTP API、WebSocket、健康检查。
- `cmd/multica`：CLI 和 daemon 入口。
- `cmd/migrate`：数据库 migration。
- `internal/handler`：领域 handler，例如 issue、agent、squad、prompt evaluation。
- `internal/service/task.go`：任务入队、领取、运行、完成和失败。
- `internal/realtime`：WebSocket hub。
- `pkg/db/queries`：sqlc 查询。

## 前端

- `apps/web` 使用 Next.js App Router。
- `packages/views` 不直接依赖 Next 或 React Router，通过导航适配器复用到桌面端。
- `packages/core` 放 API client、类型、Zustand store 和跨端业务逻辑。
- TanStack Query 管理服务端状态，Zustand 管理客户端状态。

## 任务和观测

Agent 任务的主链路是：**入队 → 领取 → 运行 → 完成/失败**。后端会记录：

- task 状态和失败原因。
- task message。
- task usage。
- task trace event。
- issue、小队、SOP run、训练评估 run/trial/evidence snapshot 的关联证据。

## 多租户

所有核心表都按 `workspace_id` 隔离。请求通过 workspace slug、workspace id 或当前路由上下文解析工作区，并在 handler 中做成员权限校验。
