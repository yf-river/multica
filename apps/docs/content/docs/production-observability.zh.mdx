部署完成后，先确认服务就绪，再用实际工作区验证 Agent 和评测链路。不要只把“进程已启动”当成可用证据。

## 健康与就绪检查

```bash
curl -fsS http://127.0.0.1:8080/health
curl -fsS http://127.0.0.1:8080/readyz
curl -fsS -o /dev/null -w '%{http_code}\n' http://127.0.0.1:3000/login
```

`/health` 只表示 backend 进程仍在响应；`/readyz` 还会检查数据库和 migration。只有就绪检查通过后，才继续验证业务流程。

如果 shell 配置了 HTTP 代理，而你正在访问内网地址，可以给 `curl` 加 `--noproxy '*'`，避免请求被代理转发。

## 页面验证

登录工作区后打开：

```text
/{workspaceSlug}/evaluation/runs
```

在**评估 → 评测记录**中检查最近一次真实运行。展开记录后应能看到运行状态、触发来源、创建者、开始和结束时间、任务标识、模型、运行时、用例结果、任务消息、trace 事件和 token 用量。失败的运行必须显示真实失败原因，不能表现为成功。

对当前部署做最小回归时，至少实际完成一次：

1. 创建或选择一个可用 Agent。
2. 创建一条 issue 并分配给该 Agent。
3. 等待任务被 daemon 领取并完成或明确失败。
4. 检查 issue 评论、任务状态、运行证据和用量记录是否对应同一次执行。

## 工作区观测摘要

```bash
curl -fsS \
  -H "Authorization: Bearer <PAT>" \
  "http://<server-host>:8080/api/workspaces/<workspace_id>/observability/summary"
```

可选过滤参数为 `since`、`squad_id`、`project_id` 和 `agent_id`。响应汇总 SOP 执行、任务状态、队列和执行耗时、token、预估成本、失败原因、模型及运行时分布。

<Callout type="warning">
观测摘要有查询上限。`summary_completeness` 表示结果是否可能被截断；结果不完整时，应缩小时间或资源范围后再判断。
</Callout>

## 评测与运行证据 API

工作区上下文由当前认证和 `X-Workspace-ID` 决定：

```bash
curl -fsS \
  -H "Authorization: Bearer <PAT>" \
  -H "X-Workspace-ID: <workspace_id>" \
  "http://<server-host>:8080/api/prompt-evaluation-summary"

curl -fsS \
  -H "Authorization: Bearer <PAT>" \
  -H "X-Workspace-ID: <workspace_id>" \
  "http://<server-host>:8080/api/prompt-evaluation-runs?limit=20"

curl -fsS \
  -H "Authorization: Bearer <PAT>" \
  -H "X-Workspace-ID: <workspace_id>" \
  "http://<server-host>:8080/api/prompt-evaluation-runs/<run_id>/evidence"
```

运行证据包含 `run`、`trials`、`task_usage`、`task_messages` 和 `trace_events`。这些对象应指向同一条运行和任务；缺失数据应以明确的空结果或失败状态表示，而不是由前端补造成功证据。

需要持久化某次运行证据时，可以创建并读取服务端快照：

```bash
curl -fsS -X POST \
  -H "Authorization: Bearer <PAT>" \
  -H "X-Workspace-ID: <workspace_id>" \
  "http://<server-host>:8080/api/prompt-evaluation-runs/<run_id>/evidence-snapshots?snapshot_type=manual"

curl -fsS \
  -H "Authorization: Bearer <PAT>" \
  -H "X-Workspace-ID: <workspace_id>" \
  "http://<server-host>:8080/api/prompt-evaluation-runs/<run_id>/evidence-snapshots"
```

## 日志检查

自部署环境可直接查看当前服务日志：

```bash
docker compose -f docker-compose.selfhost.yml logs --tail=200 backend
docker compose -f docker-compose.selfhost.yml logs --tail=200 frontend
multica daemon logs --lines 200
```

把日志时间窗口对准刚才执行的业务流程，确认没有 panic、重复派发、权限拒绝、事务半完成或持续重试。涉及外部 provider 的失败，应同时保留 provider 错误、任务失败状态和 trace 证据。
