---
title: Sign-in and signup configuration
description: Configure account/password sign-in, signup controls, and workspace creation controls.
---

Multica uses account and password sign-in. When signup is enabled, the first
successful login for an account creates that account. Later logins require the
same password.

## Signup Controls

| Variable | Purpose |
| --- | --- |
| `ALLOW_SIGNUP` | Set to `false` to block new account creation. Existing users can still sign in. |
| `ALLOWED_ACCOUNTS` | Optional comma-separated allowlist of exact account names. When non-empty, only listed accounts can be created. |
| `DISABLE_WORKSPACE_CREATION` | Set to `true` to make `POST /api/workspaces` return 403 for every caller. Users can only join workspaces they were invited to. |

Changes take effect after restarting the backend. The web UI reads
`ALLOW_SIGNUP` and `DISABLE_WORKSPACE_CREATION` from `/api/config`, so no web
rebuild is needed.

## Recommended Private Setup

1. Start with `ALLOW_SIGNUP=true` and `DISABLE_WORKSPACE_CREATION=false`.
2. Sign in with the admin account and create the shared workspace.
3. Set `DISABLE_WORKSPACE_CREATION=true`.
4. Optionally set `ALLOWED_ACCOUNTS` to the accounts allowed to join.
5. Restart the backend.

If `ALLOW_SIGNUP=false`, users without an existing account cannot accept
invitations because they cannot create the account needed to sign in.
