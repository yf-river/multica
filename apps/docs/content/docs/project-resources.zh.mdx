title: 项目资源
description: 把工蜂仓库、GitHub 仓库或本地目录绑定到项目，让智能体获得当前任务的代码上下文。
---

**项目资源（Project Resource）** 是绑定到[项目](/projects)的代码位置。项目里的 issue 被智能体领取时，守护进程会把资源清单写入 `.multica/project/resources.json`，并把简短摘要加入智能体上下文。

当前只支持三种资源类型：

| 类型 | 用途 | 当前入口 |
|---|---|---|
| `gongfeng_repo` | 腾讯工蜂项目、分支、commit、tag、文件或 MR | Web、Desktop、API |
| `github_repo` | 可通过 HTTP(S) 或 SSH checkout 的 Git 仓库 | CLI、API |
| `local_directory` | 某台守护进程机器上的现有目录 | Desktop、CLI、API |

服务端会拒绝其他 `resource_type`。类型创建后不能原地改变；需要换类型时，删除旧资源再创建新资源。

## 工蜂仓库

Web 和 Desktop 的项目资源面板读取当前工作区已登记的工蜂仓库。添加后，系统保存规范化的 `gongfeng_repo`：

```json
{
  "resource_type": "gongfeng_repo",
  "resource_ref": {
    "url": "https://git.code.tencent.com/ChainWeaver/ida/user-center",
    "project_path": "ChainWeaver/ida/user-center",
    "resource_kind": "project",
    "default_branch_hint": "v5.0.0_dev"
  }
}
```

`resource_kind` 只接受 `project`、`branch`、`commits`、`commit`、`tag`、`file` 或 `merge_request`。项目路径必须已登记在当前工作区仓库清单中，避免把任意外部 URL 伪装成受信任的工蜂资源。

资源面板的 **同步** 操作会通过当前用户的工蜂凭据刷新仓库信息。任务需要特定 revision 时，应明确选择分支、tag 或 commit；资源 URL 本身不等于已经读取了远端内容。

## GitHub 或其他 Git 仓库

CLI 的 `--repo` 快捷参数创建 `github_repo`：

```bash
multica project create \
  --title "Agent UX" \
  --repo https://github.com/multica-ai/multica

multica project resource add <project-id> \
  --type github_repo \
  --url https://github.com/multica-ai/multica \
  --default-branch-hint main
```

`github_repo` 接受有效的 HTTP(S) 或 SSH Git URL。守护进程按需通过 `multica repo checkout <url>` 获取仓库；项目级仓库会加入这次任务的允许列表，不要求事先登记为工作区仓库。

## 本地目录

`local_directory` 让智能体直接在某台守护进程机器的现有 checkout 中运行，不 clone、不创建 worktree：

```bash
multica project resource add <project-id> \
  --type local_directory \
  --local-path /Users/me/code/big-game \
  --daemon-id <daemon-uuid> \
  --ref-label "主开发目录"
```

Desktop 提供原生文件夹选择器；Web 不读取操作系统路径，因此不显示该入口。同一项目在同一台守护进程上最多绑定一个本地目录。

路径必须：

- 是存在且可读写的绝对目录；
- 不是系统根目录、用户主目录或系统配置目录；
- 解析 symlink 后仍满足上述限制。

同一真实目录上的任务会串行执行。智能体直接看到当前分支和未提交修改；Multica 不会自动 stash、切分支、commit、push 或创建 PR。守护进程只清理自己在 `workspacesRoot` 下的运行产物，不会物理删除用户目录。

## 多种资源一起使用

如果领任务的守护进程有匹配的 `local_directory`，任务在该目录运行；其他机器仍可使用项目里的仓库资源。所有资源都会保留在 `.multica/project/resources.json` 中，供智能体按任务需要读取。

项目创建及批量挂载资源在同一个事务中完成：任一资源校验失败，整个创建操作回滚，不会留下只挂了一部分资源的项目。

## 智能体收到什么

结构化文件包含项目 ID、标题和完整资源数组；智能体指令只保留便于定位的摘要。仓库资源需要 checkout 时使用：

```bash
multica repo checkout <url>
```

工蜂页面 URL 会被规范化；任务指定了 revision 时，再加 `--ref <branch-or-sha>`。资源读取失败会留下明确错误，不应把 URL metadata 当作远端内容或 MR 状态的证据。
