---
title: ログインとサインアップの構成
description: アカウント/パスワードログイン、サインアップ制御、ワークスペース作成制御を構成します。
---

Multica はアカウント名とパスワードでサインインします。サインアップが有効な場合、最初の成功したログインでそのアカウントが作成されます。以後は同じパスワードが必要です。

## サインアップ制御

| 変数 | 目的 |
| --- | --- |
| `ALLOW_SIGNUP` | `false` にすると新規アカウント作成をブロックします。既存ユーザーは引き続きサインインできます。 |
| `ALLOWED_ACCOUNTS` | 任意。カンマ区切りの正確なアカウント名許可リスト。空でない場合、一覧にあるアカウントのみ作成できます。 |
| `DISABLE_WORKSPACE_CREATION` | `true` にすると `POST /api/workspaces` は全員に 403 を返します。ユーザーは招待されたワークスペースにのみ参加できます。 |

変更は backend の再起動後に有効になります。Web UI は `/api/config` から
`ALLOW_SIGNUP` と `DISABLE_WORKSPACE_CREATION` を読むため、web の再ビルドは不要です。

## プライベート構成の推奨手順

1. `ALLOW_SIGNUP=true`、`DISABLE_WORKSPACE_CREATION=false` で開始します。
2. 管理者アカウントでサインインし、共有ワークスペースを作成します。
3. `DISABLE_WORKSPACE_CREATION=true` を設定します。
4. 必要に応じて `ALLOWED_ACCOUNTS` を設定します。
5. backend を再起動します。

`ALLOW_SIGNUP=false` の場合、まだアカウントを持たない招待ユーザーは、サインインに必要なアカウントを作成できないため招待を承認できません。
