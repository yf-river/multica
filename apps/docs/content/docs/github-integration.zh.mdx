title: GitHub 集成
description: 连接 GitHub App，同步 Pull Request 和检查状态，并把 PR 显式关联到 issue。
---

Multica 通过 GitHub App 接收 `installation`、`pull_request` 和 `check_suite` webhook。连接后，issue 详情可以显示已关联 PR 的状态、分支、改动统计和 CI 检查结果。

## 连接工作区

工作区 owner 或 admin 在 **Settings → GitHub** 点击 **Connect GitHub**。服务端生成绑定当前工作区的签名 state，浏览器完成 GitHub App 安装后回到同一个设置页。

普通成员可以查看已连接的账号；只有 owner/admin 能连接或断开安装。未配置服务端环境变量时，连接按钮保持禁用。

## PR 如何关联 issue

Webhook 只同步 GitHub 事实，不从分支名、标题或正文猜测 issue。PR 与 issue 的关系由平台显式创建，例如：

```bash
multica issue mr link <issue-id> \
  --provider github \
  --repo-url https://github.com/owner/repo \
  --number 123 \
  --title "Fix issue" \
  --html-url https://github.com/owner/repo/pull/123
```

这样可以避免 webhook 延迟或命名碰撞把 PR 关联到错误的工作区或 issue。PR、检查套件和安装查询都按工作区隔离。

## Self-Host 配置

GitHub App 至少需要：

- Setup URL：`https://<你的域名>/api/github/setup`
- Webhook URL：`https://<你的域名>/api/webhooks/github`
- Webhook 事件：`Installation`、`Pull request`、`Check suite`
- 仓库权限：读取 Pull requests、Checks 和 Metadata

服务端必填：

```dotenv
GITHUB_APP_SLUG=<github-app-slug>
GITHUB_WEBHOOK_SECRET=<random-webhook-secret>
```

可选配置 `GITHUB_APP_ID` 和 `GITHUB_APP_PRIVATE_KEY`，让 setup 回调立即查询安装账号信息；不配置时，下一条 `installation` webhook 会补齐账号名。

`GITHUB_WEBHOOK_SECRET` 同时签名安装 state 和验证 webhook 的 `X-Hub-Signature-256`。缺失 secret 时 webhook 端点返回 503；签名不匹配时拒绝请求，不会更新安装、PR 或检查状态。

完整环境变量说明见[环境变量](/environment-variables#github-集成)。
