# 质量监督交付约束

运行复盘提供「运行记录 / 质量监督」页签。后台首次登记全部业务任务，后续增量审查；数据库保存任务台账、消息覆盖范围、审查批次及问题处理历史。采用现有调度器和 Agent Runtime，不建立用户自动化，不依赖临时工作目录。

## 模型选择必须先有实测

- 优先 CodeBuddy；每家厂商只选择一个代表模型，覆盖不同积分消耗水平，模型ID和可调用性以当前账号实测为准。
- Codex `gpt-6.1-sol` 是同题基准。CodeBuddy 内的同名模型单独列出，以识别运行时差异。
- 首轮采用冻结、答案独立的监督评测集，覆盖真实问题、无问题反例、授权、最新决定、跨模块映射、误报、覆盖缺失、长轨迹和增量读取。重复运行并保存全部原始调用及结果。
- 入围模型继续进行实际工具使用、补读、跨轮审查、结构化提交及 int 真实监督任务测试。材料判断成绩不代替端到端验收。
- 质量优先：分别报告关键问题召回、误报、证据有效性、结论边界、重复稳定性、运行失败率；另报告耗时、token和实际返回积分。不把美元0当免费，不编造未返回的价格。
- 报告排名是本评测集的表现，不是通用模型能力结论。按独立案例分析差异，重复采样不冒充新增独立样本。
- CodeBuddy 无法达到基准质量时保留 Codex 6.1-sol；不因费用较低自动降低监督质量。最终候选需通过完整联调后才作为默认推荐。

## 交付门禁

用户以 `/note` 开头的评论是给监督者的备注，必须纳入变更接收、首次全量和增量材料；详情标识「用户监督备注」。备注用于定位用户关切，不能单凭主观反馈判定缺陷，不自动转换为给原负责人的修改指令或触发任务。评测覆盖漏读备注、错误派发、依据实际产物确认缺陷以及核验后无缺陷的反例。

全量/增量、审查中变更、迟到消息、大结果补读、重启恢复、重复回调、权限和问题闭环均须验收。授权包括本功能提交及 int 验收后主分支推送。用户最新决定：最终生产发布前必须取得用户明确确认；int 验收通过不自动提交生产发布请求。先交付模型榜单、联调结果、候选提交、产物身份及剩余问题，再等待生产发布确认。失败不发布，生产失败恢复旧程序。默认监督配置关闭，用户选择 Agent 后启用。
