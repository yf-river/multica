# Mika 全局协调

Mika 协调目标、依赖、异常和收尾；开发负责人负责实现，既有发布器负责共享环境。当前工作区的 IDA、ChainWeaver 和 Multica 开发统一交 ida-developer，项目规则通过对应技能读取。

## 指令与技能真源

- 默认模板：`server/internal/service/builtin_agents/mika/INSTRUCTIONS.md`。只在创建 Mika 时写入，升级服务不覆盖现有工作区自定义指令。
- 协调技能：内置 `multica-coordinating-work`。正文提供决策流程，故障案例按需读取；随服务版本发布，由运行时技能目录发现，不另建重复工作区技能。
- 现有 Mika：通过正常 Agent API 更新当前工作区指令，保留既有项目分工。修改后分别核对数据库回读、实际运行的 Agent Identity 和技能正文/支持文件；不能仅验证源码或 Agent 列表。

## 接手与停止

协调任务保存被跟进的原任务、已有授权、停止条件、依赖和下一事件。已有执行不重复唤醒，已完成验收不重复创建。协调者也需要可恢复的真实事件链路；普通关注、普通评论和仅保存清单都不自动订阅独立任务。真实委托完成或取消时，终态 outbox 消费者向源协调任务投递一次结果；沿用已有失败恢复的持久评论、消费回执和有界恢复。回执本身不能再次反向唤醒，发布暂停不触发额外回执。没有真实委托来源的历史任务不会自动订阅，使用正常有来源的续接或已有子任务阶段/队长回执，具体边界见协调技能 source map。

等待三分钟无实质进展触发一次定向诊断，不代表自动取消。有效长任务继续，失效租约或错误前置条件先修原因。同因未修复不重复重试。发布前预检、候选固定、授权与生产验收仍以环境发布文档和正常接口为准。

## 验收

先确认实际 Agent 身份与技能加载；再让 Mika 在授权范围内接续真实协调任务。验证能区分运行、等待和失败，依赖完成后正常接续且不重复派发；中断后从原任务和交付恢复。生产收尾必须核对实际版本、就绪和真实业务。

汇总实际阶段耗时、失败尝试和可取得用量，不能将并行时间相加或把缺失用量记成零。历史案例的路径、SHA 和任务编号只留在证据，不写入常驻提示词。
