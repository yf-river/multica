# DSH 计划评审与普通问答：2026-10-26

GONG-94 当前为本地实现与验收阶段，尚未提交固定 verify/int 验收，生产未发布。

## 用户行为

启用 daemon 的 `MULTICA_DSH_INTERACTIONS=1` 后，DSH 提交计划时显示完整 Markdown 和反馈输入。批准创建唯一续跑任务，以原生 `/plan off` 执行；继续规划以 `/plan` 续跑，不能执行实施步骤；取消和过期不创建任务。普通问题也通过卡片回答并续接原生会话。

等待期间原生进程退出，工具通过 DSH 的取消与会话持久化接口收尾。任务变成 `waiting_plan` / `waiting_input`，释放运行槽位和 profile 执行锁，同时撤销任务令牌。受管环境检查点保存执行归属和工作位置，不保存任务令牌。续跑恢复原生历史与受管 worktree，禁止缺失会话时自动从头执行。

## 共用边界

公共交互表、API、核心 schema 和卡片来自 `36a7bda8ca8aa8d4486d4f972591f2417d7016d1` 的公共层子集；未合入该会话的 Codex/CodeBuddy transport 改动。DSH 扩展同一张 `task_interaction`，未新增并行的计划审批表。另一个仓库的 CodeBuddy SDK provider 不在本交付中。

数据库变更：672–674 公共层；681–685 为持久化续跑、DSH provider、等待状态、后续任务唯一索引和过期扫描索引。索引各自单语句并发创建，没有新增外键。普通取消、归档和权限撤销覆盖等待任务；终态事务使未答请求失效；后台每轮最多处理 32 个过期交互。
