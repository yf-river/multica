# Codex 会话运行优化

## 交付范围

目标是缩短重复启动与上下文准备的开销，并让执行过程中的证据可以完整查看。
保留 provider 边界；调查模式、固定调查提示词、Intent Router、自然语言批量任务 API
和环境 Inventory 均不在本次范围。

## 当前实现：输出记录与装载证据

- Daemon 上报 provider 已交付的工具输出，移除原有 8192 字节裁剪。
- 既有服务端脱敏和 PostgreSQL 文本清洗继续在写入前执行。
- 消息广播、列表及执行树携带 8192 字符预览、消息 ID、字符数和预览标记。
- 输出沿用 `task_message.output` 存储，生命周期与原消息一致，无新增文件清理链或迁移。
- 完整输出通过原消息入口的 `output_id`、`offset`、`q` 参数读取，沿用工作区和任务可见性检查；SQL 同时限定 task ID 与 message ID。聊天记录校验创建者及私有 Agent 可见性；任务令牌仅能读取同一 Agent、同一聊天的执行记录。
- 网页检查器按页读取并搜索，查询缓存包含工作区；CLI 提供相同能力。
- Codex 事件缓冲区满时使用可取消的背压，避免正常运行中直接丢弃工具结果。
- 每轮生成 `CODEX_HOME/skills-manifest.json`，记录实际安装的技能名称、描述、SKILL.md 路径、真实路径和正文 SHA-256；提示词提供本轮目录位置，避免恢复会话引用上一任务目录。
- 用户技能与工作区技能冲突判断使用实际分配的完整 slug 集合。
- 共享技能目录整体装载失败、Codex 运行规则写入失败会终止准备。单个不可解析的用户技能仍按既有机制告警并跳过。
- 内容相同的受管运行规则文件无需重复写入。

这里的“完整”指 provider 通过现有协议交付、经过脱敏及数据库文本清洗后的输出。
Codex 原生工具本身的裁剪、SDK 对部分结构化补丁的预算、历史上已丢弃的内容均不由这条记录链恢复。
原有消息上报在网络失败时没有幂等重试；移除裁剪不等于已提供端到端无损投递保证。

## 尚未完成

1. **常驻 app-server 和热 thread**：现有 `executeOnce` 仍按轮创建和回收进程。
   进程继承任务令牌、CODEX_HOME、临时目录；MCP broker 和插件 hook server
   也在任务结束时关闭。复用前必须让轮次资源与会话资源各自有明确生命周期，
   验证下一轮不会使用旧任务凭据。不能只删除进程回收或按 runtime ID 缓存 backend。
2. **会话配置版本与更新**：技能清单目前是装载快照；还没有完成稳定挂载、bundle
   内容缓存、运行规则/技能/MCP 改变后的热会话失效或重建策略。
3. **取消、恢复与空闲回收**：常驻路径需独立验证 turn/interrupt、崩溃后的持久化
   thread 恢复、同会话互斥、跨会话并发、账号/权限/配置隔离及进程树回收。
4. **阶段耗时界面**：现有生命周期日志继续生效；尚未新增前端阶段时间展示。
5. **联调与性能验收**：尚未完成真实 Codex 多轮、数据库权限、浏览器及同条件冷/热
   对照。没有性能提升结论，也没有生产发布。

## 下一步验收顺序

1. 按仓库发布规则取得本地 commit 授权，准备干净候选到固定 int；不使用 prod 数据测试。
2. 通过真实聊天工具执行生成大于 100KB 的中文输出，在末尾加入唯一可搜索标记。
   比较原生输出、数据库记录、WS 预览、页面分页及 CLI 检索；验证脱敏、刷新恢复和跨任务/跨工作区拒绝访问。
3. 检查实际 Codex 发现的技能路径与清单一致；覆盖技能修改、删除、不可读路径及同名冲突。
4. 基于真实轮次资源建立常驻路径，完成上述隔离、取消和恢复测试。
5. 用相同模型、effort、tier、输入和环境测量冷启动与连续三轮热会话，分别记录准备、握手、首个事件、工具执行和最终输出时间。模型容量错误单列，不算作平台耗时。
6. 完整范围与浏览器验收通过后才能记录 release acceptance 和请求生产更新；未完成项不能以本地测试替代。
