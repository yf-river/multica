# 饮食安排与备餐

饮食页按本人和工作区保存专业数据，统一助理负责沟通并提交待确认菜单。正式餐单确认、采购状态、实际入库和取用由本人操作。

## 用户流程

1. 在饮食页填写偏好，或选择“一起安排这周”，在统一助理中沟通目标、活动、忌口、用餐人数、外食餐次、已有食材及备餐时间。
2. 助理读取本人身体数据和现有菜谱，提交菜单建议。每份用量区分菜谱原量、助理建议和用户调整；未知量留空，其他人的食用量单独沟通。
3. 在待确认菜单中编辑餐食与用量，确认后生成正式餐单、采购清单和计划备餐。已有餐单在讨论期间变化时，旧草稿不能覆盖它。
4. 采购清单可以手工调整和标记已有、已购买；执行事项可以创建或关联现有任务。
5. 查看菜谱做法和集中备餐安排。实际制作后记录批次，取用后记录份数，剩余数量按取用记录计算。

身体数据更新提示重新评估，已确认餐单不会自动改变。任务完成不等于购买、制作或入库完成。菜谱及收藏复用原有接口和图片；饮食进入烹饪指南的 URL 上下文限定为同工作区内部路径。

## 数据与接口

`meal_workspace` 按 `(workspace_id,user_id)` 保存带版本的饮食集合。JSONB 包含偏好、餐食、采购来源、备餐计划、实际批次、取用、讨论草稿及执行任务关联。511 建表，512 单独并发建立作用域唯一索引；没有外键或级联。

- `GET /api/meals`：当前本人数据、饮食版本、身体数据版本和关联任务的真实状态。
- `POST /api/meals/actions`：具名业务操作；revision 检查编辑冲突，request_id 对提交重试去重。取用在集合行锁内校验余量，不能超额扣减。
- Agent 只能在本人发起的运行中任务内读取及提交 `draft_save`。菜单确认和实际记录不能由 Agent 直接写入。
- 执行任务调用既有 `IssueService.Create`，使用 `RelatedRecord` 在同一事务登记来源关系。关联以清单或备餐计划的稳定 ID 去重，不依据任务标题。

食材合并键包含名称、单位和数量口径；无明确数量、单位或口径的条目保留独立来源。重新整理保留手工数量及采购状态，已移除餐单的来源显示待检查。收藏沿用原有跨工作区规则；其他饮食数据不跨工作区共享。

## 集成与发布

使用现有 int 源码快照叠加饮食修改，通过已有发布脚本及锁构建、发布。新增表兼容旧程序；回滚程序不删除饮食数据。限定执行 511、512 迁移，不重放现有环境缺失的历史迁移，也不使用身体数据或烹饪指南专用发布脚本。

Agent 命令与结构化草稿协议见 `server/internal/service/builtin_skills/multica-meals/`。验收要求真实统一助理提交、本人确认、刷新持久化、采购调整、任务去重及实际批次取用，覆盖桌面和 390px；只清理验收新建的数据。

账号或工作区硬删除时，应用清理流程应在同一事务删除对应 `meal_workspace` 行；不通过数据库外键推断属主关系。
