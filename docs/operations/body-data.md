# 身体数据与体检报告

身体数据按工作区和本人隔离。最后导入的同类结果成为当前指标，补录旧报告也覆盖涉及项目，其他指标不变。测量日期独立保留，原报告、原始结果、参考区间和页码分别保存。报告上传和右下角助手的“上传体检报告”使用同一个私有接口。

## 日常记录与 BMI

手工新增入口提供体重、血压、心率和身高，输入结果与日期；已有报告指标保留结果和日期的修正入口。新增批次排在当前采用集合最前面，批内顺序和其他项目相对顺序保留，恢复读取快照顺序。总览接口的 `computed_bmi` 是可空的计算结果，包含数值、单位及采用的身高和体重来源记录。它不生成实测记录或额外版本；缺少有效数值或单位时为空。首页使用计算 BMI，原报告 BMI 与理想体重保留在报告及历史中。已有分析保留生成版本，不因显示变化重新执行。

## 存储与读取工具

`HEALTH_STORAGE_DIR` 指定持久的私有目录；未指定时使用 `LOCAL_UPLOAD_DIR` 后缀 `-health` 的姊妹目录，不能将该目录挂到公开 `/uploads`、CDN 或静态文件服务器。原件与 OCR 缓存随环境持久保存，不属于发布目录。目录权限 0700，私有 JSON 和原件权限 0600。备份时同时备份数据库与此目录。

API 主机需要 Poppler（pdfinfo、pdfimages、pdftotext、pdftoppm）与 Tesseract 的 chi_sim、eng 字库。输入保留原件，每页保存文字和坐标，扫描页与大图页进行 OCR；渲染长边限制为 2400px，疑点仍需原件核对。首轮准备可能持续几十秒；相同摘要的报告去重，重试复用已准备页面。

## Agent 处理

内置 multica-body-data 能力和 `multica health` CLI 随发布二进制下发。助手通过报告引用创建任务，返回链接后结束聊天轮次。执行任务先 prepare，再每批读取至多四页；先用 submit 的 extraction 阶段保存指标，再用 analysis 阶段提交引用数据版本的分析。CLI 按回执更新现有任务状态。分析失败不删除已入库数据，重试保留原任务条目并只补分析。

缺单位、日期、身份差异、证据无法定位或 OCR 识别疑点写入来源说明，指标直接录入，不设置人工确认门槛。分析保存成功即完成任务；真实读取或分析失败仍明确报错。报告处理任务的详情、日志和实时订阅只允许本人；原件不绑定普通聊天附件。不要在普通日志或回复中输出报告全文、指标值或密钥。

## 恢复与迁移

身体数据保留当前状态及最近十个旧状态，快照包含指标记录集合和当前采用集合。恢复写入新版本并增加 epoch，使旧任务回调失效；原报告和历次提取结果保留。没有采用集合的既有快照按其原有日期和确认状态还原。本人通过 `POST /api/health/reports/{id}/apply` 或 `multica health report apply <id> --revision N` 应用已有提取，整批保存一个版本，不重跑模型或改写原始提取结果。手工录入通过 `POST /api/health/observations` 保存；血压等成组测量使用 `observations` 数组在同一事务和数据版本中写入。正式页面不设置人工确认或逐条采用按钮。快捷更新保留旧测量用于趋势，手工修正保留原始证据。删除工作区时，应用事务明确清理健康表，提交后清理该工作区私有文件。

新增迁移为 501—510。索引均为独立文件内的 CREATE INDEX CONCURRENTLY。509 扩展任务来源白名单以接受 health_report，510 单独校验约束；存在体检任务时拒绝回滚 509，避免既有任务无法更新。联调从既有 schema 快照升级时，只向标准迁移器提供这组新增迁移，不能补写或重放历史迁移台账。迁移后核对五张表、六个索引、chat_message.health_report_ids 与任务来源约束的实际状态。发布入口不会自动执行迁移。

验收须包含真实 PDF 的全部页面、真实 Agent 入库与分析、手工修正、版本恢复、跨用户/跨环境访问拒绝和浏览器页面错误检查。默认测试不调用真实 Agent；真实报告读取与数据库事务验证分别通过 MULTICA_HEALTH_REPORT_FIXTURE 和 MULTICA_HEALTH_DB_TEST 显式启用。
