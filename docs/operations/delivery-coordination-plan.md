# 交付协调与发布暂停续接

执行任务：GONG-54（交付归属、验收复用和发布串行）、GONG-56（发布窗口与任务续接）。

用户已在 Codex 会话确认本计划，并授权开发、测试验收、提交推送、主分支整合、生产发布、截图、评论和验收通过后关闭对应任务。当前会话负责实施，不另行派发开发 Agent。

## 交付协调

- 每个任务只有一个有效交付负责人，租约通过心跳续期；接续需要显式核对，递增代次隔离旧执行者。
- 同任务、方案与提交重复提交返回已有交付。替换提交须明确指出旧交付及版本，保留证据。
- verify 槽位并行验收，固定 int 到 prod 串行；最终集成期间固定主分支、生产基线与候选，所有发布者遵守同一持久占用。
- 冲突返回原任务修复并释放通道；精确相同的验证输入复用证据，变化按声明的覆盖范围补测，未知影响、结构或依赖变化执行完整相关检查。
- 验收与授权分开保存，授权变化只重新核对范围。生产应用同一验收产物。
- Agent 提交后结束运行；发布器异步推进并幂等通知，避免发布器和 Agent 互相等待。

## 发布窗口

构建和预检查通过后停止本环境接单。已有任务有 120 秒自然完成时间，其后请求中断；提供商的既有终止流程回收执行进程，发布器最多再等 60 秒完成进程及检查点确认。未确认停止则退出切换并保留恢复记录，不强杀整个 Daemon。

发布暂停使用独立原因和清单，保留会话、分支、未提交代码、任务目录及原执行关联。暂停路径不自动提交或删除任务 worktree。新请求留在队列；不影响其他环境和独立 SSH/Codex 会话。

发布成功或旧版恢复并健康后，按原 Agent、原执行和工作目录建立唯一续接。优先原会话；没有会话但代码完整时带执行记录继续。会话、目录或操作结果存在无法自动核对的缺口时，记录对应任务异常，不冒充恢复成功。

续接必须先核对中断前最后操作：Git 引用、交付记录、实际部署及外部写入结果。未知结果不能直接重发；人工取消、自然结束、改派或已有更新执行的任务不能被重复唤起。

窗口与恢复清单持久化；发布器或服务重启后接续同一记录。保存失败、停止未确认或旧版恢复失败时保留现场。恢复记录分别证明排队、启动、继续产生业务进展。

## 验证与交付顺序

1. 核对独立 worktree 和已有实现，从剩余项继续，不覆盖其他任务。
2. 补齐租约、自动验收、授权复核、通知去重、脚本打包及故障恢复。
3. 实现发布暂停清单、工作目录保留、专用停止确认、自动续接及状态展示。
4. 独立真实数据库验证并发登记、A/B/C 串行发布、过期身份、证据复用和恢复去重。
5. 真实文件与受控进程验证中断保存；固定测试环境验证暂停、切换、恢复，执行真实 Agent 续接并截图。
6. 提交推送任务分支，通过正规队列最终集成、补测和授权复核后，推送主分支并晋级同一产物。
7. 首次升级旧 Daemon 不具备新协议，须通过旧协议形成一次受控空闲窗口；工作成果和停止确认不完整则保留旧服务。
8. 生产核对版本、登录、页面、API、WebSocket 和任务实际续接，自动评论和保存截图，满足全部停止条件后关闭任务。

仅覆盖当前 Web、Server、Daemon、Agent Runtime 与 PostgreSQL。冻结客户端不在范围内。数据库仅新增兼容表和独立并发索引，不清理生产数据。

完成条件：登记幂等、验收有效复用、发布互斥、长任务可受控暂停、任务自动正确续接、异常可重启恢复均通过实际验收，且生产版本与验收产物一致。
