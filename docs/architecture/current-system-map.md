## Static-analysis limits and manual review points

- **chi-parser:** The Go route inventory resolves literal r.Route prefixes and literal verb registrations in server/cmd/server/router.go. Computed paths, helper-owned routers, Mount/Handle registrations, build tags, and runtime conditionals require a manual override.
- **database-model:** The database inventory replays CREATE/DROP declarations from ordered up migrations for tables, functions, triggers, and indexes. It does not connect to a running database, expand every inline constraint, or detect environment-specific schema drift.
- **desktop-parser:** Desktop paths are recovered from literal path properties in the appRoutes RouteObject tree. Index routes, Navigate targets, overlay transitions, and paths created outside that tree are not route literals.
- **environment-parser:** Environment discovery covers literal and same-file constant Go os.Getenv/LookupEnv calls, common Go env helpers, Node process.env/import.meta.env access, Docker Compose template references, and .env.example declarations. Dynamically constructed names, general shell-script variables, CI secrets, and values are intentionally excluded.
- **external-io-parser:** Automatic external-I/O detection identifies concrete library and syscall primitives, not business semantics or delivery guarantees. Named external systems are maintained as evidence-backed manual overrides.
- **inventory-not-domain-map:** This generated inventory is a drift-checked architecture input. It does not replace maintained domain-flow documentation that connects UI/query keys through HTTP, handlers, services, SQL, events, failure recovery, and user-visible outcomes.
- **react-query-parser:** React Query counts are syntax-level call counts in production TypeScript sources. Wrapper hooks and aliased imports may hide calls; a call count is not a count of unique server-state domains.
- **websocket-difference:** Go-versus-TypeScript event differences and production reference sources are reported mechanically. Reference presence does not by itself distinguish producer from consumer; daemon/internal contracts and dynamic dispatch still require human classification.

When a current runtime surface is dynamic or cannot be recovered safely from
source syntax, add a narrow record to `docs/architecture/current-system-map-overrides.json`. Overrides are part
of the drift check and must include concrete evidence; they are not a place for
future architecture proposals.
